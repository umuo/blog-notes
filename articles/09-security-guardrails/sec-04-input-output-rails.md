同样一句「退款记录有两条」，可能来自允许公开的资料，也可能来自内部数据。护栏是应用在入口、模型调用、工具和输出之间加的规则。先确定每个阶段允许什么，再用带标签的小样本检查规则是否按预期工作。 [NeMo Guardrails 项目](https://github.com/NVIDIA-NeMo/Guardrails)

## 1. 入口规则只负责发现一类情况

本例构造四条合成样本，人工先判断是否应转复核，再运行一个简单规则。这个规则模拟格式识别，统计时把「送复核」算作阳性。

| 人工判断 | 规则送复核 | 规则放行 |
| --- | ---: | ---: |
| 应复核 | 1（正确送审） | 1（漏判） |
| 可直接通过 | 1（误拦） | 1（正确放行） |

本组误拦率是 `1 / 2`，分母是人工标为可通过的 2 条。漏判率也为 `1 / 2`，分母是人工标为应复核的 2 条。四条是教学样本，不能用来估计线上比例。业务可把确定要拦截的类别与不确定、需要人工复核的类别分开计分。入口还应设大小上限和失败处理，以减少无谓重试。

## 2. 结构校验、证据范围和展示各做一件事

输出用 JSON（JavaScript Object Notation，文本数据格式）。Schema 只接受答复文字 `answer` 和证据 ID `evidence_id`。引用 ID 必须在本轮已经授权的证据包里。页面拿到的是作为 HTML（HyperText Markup Language，网页标记语言）文本显示的值。`4 < 6` 里的小于号编码为 `&lt;`，用户仍看到原来的比较式。

| 输入情况 | 实测结果 |
| --- | --- |
| 合法结构，证据在包内 | 显示经编码的文本 |
| 无法解析 JSON 或有额外字段 | 拒绝该输出 |
| 合法结构，证据却不在包内 | 拒绝该引用和答复 |
| 复核依赖不可用 | 返回不可用，停止公开原输出 |

引用存在检查的是位置，事实忠实度还要回看原文。仍有独立工具执行的应用，要让工具代理校验授权。本例在本机对合法答复重复校验 1,000 次，P50（中位数）约 1.8 微秒，P95（按用时排序的第 95 百分位）约 1.9 微秒。测量包含 Python 函数内的解析和检查，不包含网络、模型或人工复核。用 `--latency` 可以测自己的运行环境。 [实验代码](../../experiments/agent-guardrails/guardrails_lab.py) · [确定性结果](../../experiments/agent-guardrails/guardrails-results.json)
