## 先用大白话理解

你昨天把一张单放在柜台，票上写着“均值 5.00 元，等签字”。今天换了一套柜台系统，新单按“500 分”存。昨天的客人回来签字时，系统需要按昨天的写法读懂那张票。它已经做好报告，直接用这份报告继续。签字后归档重试，也只能产生一份收据。

这份票对应 Agent 的在途任务，也就是已经开始、还未走到成功或取消终态。例子里的 CSV（逗号分隔值文件）包含 8.00 元、2.00 元和缺失记录。统计得到两条有效数据。服务暂停在 `pending_approval`（等待人工确认）已经保存的步骤。

## 记录哪些版本，恢复时才找得到原来的规则

| 版本字段 | 样例 | 恢复时的用途 |
| --- | --- | --- |
| Prompt 版本 | `refund-prompt@3` | Prompt 是给模型的指令和上下文模板，用该引用找到旧模板 |
| 模型发布版本 | `provider/model-build-b` | 保存逻辑路由和实际供应商模型发布号，了解当时用了哪个实现 |
| 工具输入 Schema | `stats-input@1` | Schema 是参数的结构与类型约定，要用对应规则读旧参数 |
| 工具输出 Schema | `stats-output@1` | 决定如何解析历史工具结果与金额单位 |
| 任务协议和执行器 | `run-state@4`、`worker@7` | 选择能读懂等待点的执行代码 |
| 归档操作标识 | `alpha/r-17/archive` | 重试时找回同一操作的状态和收据 |

另存输入数据的稳定引用、输入摘要、审批前报告摘要和工具输出引用。模型若只提供会换指向的别名，就一起保存返回的模型字段和路由快照，并标注无法确定的实际版本。留档版本用于诊断，已记录结果用于忠实重放，两者解决的问题不同。

## 同一笔 5.00 元怎样跨格式

新输入把平铺的 `field` 改成带单位的 `column` 对象。旧输入约定 `refund_amount` 始终以元作为文件单位，适配器只把这份默认值显式写出来。

```json
{"schema": 1, "field": "refund_amount"}
```

```json
{"schema": 2, "column": {"name": "refund_amount", "unit": "CNY_yuan"}}
```

输出约定也改变。版本 1 传 `{"schema":1,"amount":"5.00","currency":"CNY"}`，版本 2 改传 `{"schema":2,"mean_cents":500,"currency":"CNY"}`。CNY 是人民币的货币代码。旧输出用十进制数解析，金额 5.00 元乘 100 得 500 分。读入后两者都变成内部结构 `{"mean_cents":500,"currency":"CNY"}`。真实工具还要验证小数位、范围、缺失含义和币种。金额单位属于字段语义，不能靠字段名相似就直接拷贝。

## 恢复和再执行，分别会发生什么

重新加载 `r-17` 时，统计阶段已经完成。运行器读到工具输出记录和报告内容，使用旧版解码继续等待原审批。已有批准绑定了具体报告字节。适配器如果只补内部字段可以继续用原报告；如果重新渲染得到不同摘要，要按新报告再批准。归档外部动作前先检查操作标识对应状态。已有收据直接用，终态不明先向目标端对账。

轨迹回放把原先的模型或工具结果注入，用它检查任务状态机能否走到同一等待点。真实重跑重新请求模型，适合衡量新版本质量；采样、有变化的上游数据和服务可用性都可能影响结果。回放用隔离目标，不触发真正的归档。引擎侧的工作进程版本管理可以固定旧任务继续用原版本，例如 Temporal 的 Pinned 工作流行为。业务仍需要保存 Prompt、模型、工具和产物引用。 [Temporal Worker Versioning](https://docs.temporal.io/production-deployment/worker-deployments/worker-versioning)

## 灰度、回滚和实验怎样对齐

先上线能读旧格式和新格式的消费者，再小比例开放新版生产者。已分配任务保留能读对应版本的执行路径。回退时停止把新任务指向新版，保留能接在途任务的工作进程，或经过可验证的迁移才转交。降级窗口里要测试旧消费者读新状态会怎样。无法读取就明确停在兼容边界并保留原数据，避免默认为缺失。最后按在途计数、最大重放期限和保留要求决定何时移除旧分支。

[演练脚本](../../experiments/production-refund/README.md)比较旧输入经适配后和新版输入的结构，两个结果都被解码为 500 分。未知输出版本以 `unknown schema` 拒绝。同一归档标识回放两次，模拟记录只有一次效果。真实生产还需覆盖重复交付、旧执行器备份恢复与外部收据丢失后的对账。下一篇把版本标识连进慢请求时间线。 [生产化专题目录](../../llm-agent-learning-roadmap.md)
